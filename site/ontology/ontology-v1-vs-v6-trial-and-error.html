온톨로지 시각화 버전 비교: v1 vs v6 (및 v8)

2026-08-27 작성 · 2026-08-28 갱신(v8_d3style, 관계망 필터 추가분 반영)
#온톨로지 #시각화 #D3 #vis-network #TTL

1. 왜 이 정리가 필요했나

v1은 내가 손으로 짠 D3.js 그래프였고, v2부터는 실제 OWL/Turtle 온톨로지 파일(.ttl)로 바뀌었다. 그런데 v3 이후 스키마가 "김바로(한국학중앙연구원) 박사논문" 방식의 제도-인사 온톨로지로 바뀌면서, v1의 그래프 코드를 그대로는 재사용할 수 없다는 게 분명해졌다. 여기서는 그 구조적 차이가 정확히 무엇이었고, 그걸 어떻게 다시 시각화 가능한 형태로 접었는지, 그리고 그 과정에서 실제로 겪은 버그들을 정리한다.

2. 구조적 차이: 이항관계 vs 사건(Event) 중심

v1의 linksData는 처음부터 끝까지 이항관계(binary relation)였다. 

["이승훈", "오산학교", "설립"]

주어-관계-목적어 세 칸이면 관계 하나가 완결된다. 그래서 D3의 forceLink에 그대로 꽂아 넣으면 끝이었다.

반면 v3부터의 스키마는 관계를 전부 Event 개체 하나로 감싼다. 예를 들어 "최린이 천도교 소속에서 독립선언서 초안 작성자로 임명됨"이라는 사건은 이렇게 기록된다. 

:19190301최린임명_01 rdf:type :Event ;
    :hasPreObject  :천도교 ;
    :hasObject     :최린 ;
    :hasPostObject :독립선언서초안작성자 ;
    :hasEventType  :임명 ;
    :hasTimeValue  "1919-03-01"^^xsd:date .

개체 하나(사건)가 이전 상태(hasPreObject)·행위자(hasObject)· 이후 상태(hasPostObject)·유형(hasEventType)·시간 (hasTimeValue)까지 한 번에 갖는다. 이건 "누가 언제 무엇을 했는가"를 출처·시점과 함께 정밀하게 남기기 위한 설계라, 학술적으로는 v1보다 훨씬 촘촘하다. 하지만 그래프 시각화 관점에서는 노드 하나(최린)가 그래프 노드가 아니라 사건 노드에 매달린 속성이 되어버린다는 문제가 생긴다.

정리하면: v1은 "관계가 곧 간선"이었고, v6~v8은 "관계가 곧 노드(Event)"다. 그래프로 그리려면 후자를 전자로 다시 접어야 한다.

3. 해결: Event를 두 개의 간선으로 접기

v6에서 택한 방법은 Event 하나를 간선 두 개로 쪼개는 것이었다.

  • hasPreObject → hasObject : 간선 1 (라벨 = hasEventType)
  • hasObject → hasPostObject : 간선 2 (같은 라벨)

위 최린임명 이벤트라면 천도교 —임명→ 최린, 최린 —임명→ 독립선언서초안작성자 두 개의 간선이 나온다. pre나 post가 없는 이벤트(예: 단순 참여·소속)는 간선 하나만 나오거나, 관계 자체가 없으면 노드만 고립된 채로 남는다. 이 로직을 ttl-parser.js + buildNetwork()(v6)로 구현하고, Node.js 환경에서 실제 v5.ttl(트리플 814개)을 미리 파싱해 노드/간선 수를 검증한 뒤에 배포했다.

4. v8_d3style — "그럼 v1 스타일 그래프도 가능한가?"

v6~v8은 이 접기 로직을 vis-network로 그렸지만, "v1처럼 D3.js 그래프로도 되는가"라는 질문이 나와서 v8_d3style.html을 따로 만들었다. v1의 CSS·필터 버튼·검색창· 상세패널 코드는 그대로 두고, 하드코딩 데이터 자리에 v8.ttl을 fetch로 읽어 위 3장의 접기 로직을 적용한 값을 채워 넣는 방식이다. 실제로 돌려보니 노드 44개(인물 30 + 조직 14, 편찬자 placeholder 제외), 간선 48개가 나왔다.

이 과정에서 흥미로운 데이터 격차를 하나 발견했다. v1은 최린·정춘수·박희도 3인을 손으로 "이후 친일 전향"이라고 표시해뒀는데, v8 온톨로지에는 현재 최린만 :전향 이벤트가 실제로 기록되어 있었다. 즉 정춘수·박희도의 전향 사실이 아직 정식 Event로 모델링되지 않은 상태다. v1은 "저자가 아는 사실을 텍스트로 박아넣은 것"이었고, v8은 "온톨로지에 기록된 것만 보여주는 것"이라 이런 차이가 그대로 드러난다 — 이걸 감추지 않고 화면과 changelog에 그대로 남겨뒀다. (참고로 이 필요성은 온톨로지를 계속 보강해야 할 이유이기도 하다.)

5. v8_with_gonghun 관계망 탭에 v1 UI 이식

v8_d3style과 별개로, 기존 v8_with_gonghun.html의 "관계망(Network)" 탭에도 v1의 필터 버튼·검색창·범례를 이식했다. 다만 D3와 vis-network는 "흐리게 표시"를 다루는 방식이 다르다.

  • D3(v1): SVG에 .dim 클래스를 토글해 opacity로 흐리게 처리
  • vis-network(v8): opacity 기반 dimming이 마땅치 않아, 대신 노드·간선 DataSet에 hidden 속성을 update()로 갱신해 아예 표시/비표시를 전환하는 방식을 씀

기능적으로는 동등하지만(유형 필터·이름 검색 모두 동작), 시각적으로는 v1이 "흐려지는" 느낌이라면 v8은 "사라지는" 느낌이라는 차이가 있다.

6. 실제로 겪은 버그들

6-1. vis-network가 숨겨진 탭에서 초기화되던 문제

v6에 관계망 탭을 처음 추가했을 때, 탭을 눌러도 계속 빈 화면이었다. 원인은 buildNetwork()가 v5.ttl 파싱 직후 곧바로 호출되는데, 이 시점에 "관계망" 탭은 아직 display:none 상태(기본 활성 탭은 "지도")라 vis-network가 0×0 크기 컨테이너에 초기화돼버린 것이었다. 관계망 탭을 처음 클릭할 때 지연 생성(lazy build)하도록 고쳐서 해결했다.

6-2. 지연 초기화 이후에도 재발

1차 조치 이후에도 v6·v6_with_gonghun·v8_with_gonghun 전체에서 여전히 빈 화면이 나오는 경우가 있었다. 이번엔 세 가지가 겹쳐 있었다.

  1. CSS grid의 auto 행 높이 계산이 브라우저 환경에 따라 불안정했다
  2. 그래프 생성 직후, 물리 시뮬레이션이 끝나기 전에 fit()을 호출해 뷰가 제대로 맞춰지지 않았다
  3. 지도 탭과 관계망 탭의 상세 패널에 id="side"가 중복 선언돼 있었다(무효 HTML)

해결: 그래프 생성 직전 컨테이너에 clientHeight 기반 픽셀 높이를 코드로 직접 지정하고, network.once("stabilizationIterationsDone", ...)로 안정화가 끝난 뒤 fit()을 호출하도록 바꿨다. 중복 id는 관계망 쪽만 side2로 분리했다.

6-3. versions-data.js 스키마 사고

한 번은 별도로 준비한 코드 조각을 붙여넣다가 const가 onst로 오타 나면서 자바스크립트 문법 오류가 났고, 동시에 필드 구조도(id/ title/summary 등) 기존 스키마(version/ label/changelog)와 달라서 오타를 고쳐도 정상 렌더링이 불가능한 상태였다. 게다가 그 코드에는 v1~v6 기존 항목이 통째로 빠져 있어서 버전 이력이 사라질 뻔했다. 기존 스키마를 유지한 채 새 항목만 정확히 추가하는 방식으로 복구했고, 이후로는 매번 "완성된 폴더 전체"를 zip으로 받아 통째로 교체하는 방식으로 이런 사고를 줄였다.

7. 지금까지의 결론

  • 이항관계 그래프(v1)와 사건 중심 스키마(v3~v8)는 표현력이 다르다 — 후자가 더 정밀하지만, 시각화하려면 반드시 "접는" 변환 단계가 필요하다.
  • 그 변환 로직(ttl-parser.js의 파싱 + Event 접기)은 재사용 가능한 형태로 분리해뒀기 때문에, v1 스타일(D3)이든 v6 스타일(vis-network 탭)이든 같은 원본 데이터에서 다른 그림을 그릴 수 있다.
  • 온톨로지에 없는 사실은 그래프에도 나타나지 않는다(정춘수·박희도 사례) — 이는 버그가 아니라 "온톨로지가 아직 다 채워지지 않았다"는 정직한 신호로 다뤄야 한다.
