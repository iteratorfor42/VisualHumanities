온톨로지 프로젝트 전체 이력: v1 → v10 (통합본)

본체(v1~v8) · Provenance 트랙(ver2~ver5, v9.1~v9.5) · 시각화 트랙(v6~v10, dh-webpage)을 하나로 병합한 최종 이력
#온톨로지 #TTL #provenance #버전이력 #v1-v10

I. 전체 개관 (간결)

일제강점기 독립운동-근대학교 온톨로지는 두 갈래로 발전했다.

  • 본체 (v1~v8) — 이항관계(v1) → 사건유형별 클래스(v2) → 단일 Event 스키마 정착(v3) → 편찬 메타데이터·도메인 확장(v4~v5) → ontology 저장소의 검증 보고서를 반영한 사실 검증(v6~v7) → 불확실성 자체의 모델링(hasValidationStatus, 신흥강습소 실체분리, v8).
  • Provenance 트랙 (ver2~ver5, v9.1~v9.5) — v8 인스턴스가 실제로 근거를 갖췄는지 확인하기 위해 별도로 시작한 Claim 중심 병렬 데이터셋. 49개 원본 항목 → 55개 Claim으로 분해 → 34 Core + 5 Hold(TTL 반영, 987 트리플) + 16 Exclusion(CSV만 보관).
  • 시각화 (v6~v10, dh-webpage 저장소) — 본체·Provenance 트랙 데이터를 브라우저에서 읽어 그리는 뷰어들. v9_5re.html에서 데이터는 그대로 두고 의미론 재검토 표시축(SEMANTIC_REVIEW)만 추가했고, v10.html은 여기에 국가보훈부 공훈전자사료관 API 연동을 시도했으나 HTTP-only API·가용성 불안정·서버 XML 명세 위반 등으로 아직 실사용 가능한 상태가 아니다 — 현재도 진행 중인 미해결 과제.

세 갈래 모두 "김바로, 『제도-인사 온톨로지 설계』"의 사건모델 (:Event 단일 스키마)을 공통 뿌리로 삼지만, Provenance 트랙은 그 모델이 표현하지 못하던 "관계 자체의 확실성"을 담기 위해 완전히 다른 스키마(Claim/Evidence/Source 분리)로 갈라져 나온 것이며, v8의 "다음 버전"이 아니라 병렬 검증 트랙이다.

II. 상세 이력 — 본체(v1~v8)

1. 전체 개요 — 세 국면

  • 스키마 전환기 (v1~v3) — 데이터를 어떤 구조로 담을지 결정. 이항관계 → 사건유형별 클래스 → 원 논문의 단일 Event 스키마.
  • 정합성·범위 확장기 (v4~v5) — 편찬 정보(누가·언제) 정리, 중복·충돌 개체 해소, 도메인을 "구한말 관공립학교"에서 "독립운동-근대학교 네트워크"로 확장.
  • 사실 검증·불확실성 모델링기 (v6~v8) — 실제 역사적 사실을 재검색해 확정하거나, 확정 못 하는 상태 자체를 구조화.

2. v1 → v2 — 이항관계에서 사건유형별 클래스로

v1은 ["이승훈", "오산학교", "설립"] 배열을 그대로 forceLink에 꽂는 D3.js 그래프였다. v2에서 OWL/Turtle로 전환하며 FoundingEvent· RoleEvent·AppointmentEvent처럼 사건유형별 클래스를 만들었다.

3. v2 → v3 — Event 모델을 기본 틀로 채택

김바로 박사논문의 Event 중심 설계를 기본 모델로 채택해 단일 :Event 클래스로 통합. 47개체·627 트리플, Protégé 정상 파싱 확인. locatedIn류 6개 관계는 Event로 바꾸지 않고 조직의 정적 상태로 남기는 것은 원 논문이 아니라 프로젝트가 임의로 정한 해석이다.

4. v3 → v4 — 편찬 메타데이터와 정합성 정리

hasCompiler/hascompiledTime 미기입 65건 보강, :백오인사건 Group/Event 이중 타입 해소, 중복 개체(:이승훈설립오산학교_01) 제거.

5. v4 → v5 — 편찬자 실체화, 도메인 확장

hasCompiler placeholder를 :iteratorfor42로 치환(68회). 다만 v5 자신은 이 단계에서 다음 문제를 방치했다: 오산학교-대성학교 succeedByPersonTo가 근거 (hasBibo) 없이 서사만으로 단정돼 있었고, 안명근체포 Event가 hasEventType :임명으로 잘못 분류된 채 방치됐으며 (:체포 Term 자체가 아직 없었음), 역사적 사건 6개 전부가 hasEestimation 없이 "1월 1일" sentinel로 남아 있었다.

6. v5 → v6 — 3회차 검토안 반영(v6_3으로 검증보고서 세 차례 작성)

필수 수정 4건: 안명근체포 유형(:체포)·시간 (1910-12-01) 정정, 오산-대성 승계관계 삭제, 오산학교 개교일 1907-12-24 확정(다출처 일치 근거, 단 이 확신은 훗날 v9 ver2에서 재반박됨 — §III 참조), 안명근체포→안악사건→백오인사건 2단계 확대구조 신설. 추가 검증 날짜 5건: 삼일운동(1919-03-01)· 봉오동전투·청산리전투·조선물산장려회(1920-08-23) 확정, 연도만 아는 설립 Event 일괄 추정 플래그 부여. 이 시점까지도 소속/참여 Event 12+9건은 언급조차 없이 공란이었다(v6 changelog에 미기재).

7. v6 → v7 — 날짜 자동상속 금지 원칙의 최초 대규모 적용

신민회/임시정부 소속 12건에 Year 추정 부여, 3·1운동 참여 9건 중 6건 확정·3건(정춘수·박희도·조만식) 예외 처리. 설립→공동설립 (:공동설립 Term 신설) 구분. 이종일의 "경영"이 보성학교 전체가 아니라 부속 인쇄소 보성사였음을 코멘트로 처음 인지했으나(v7), 트리플 자체는 아직 :보성학교로 남아 있어 "코멘트가 데이터를 정정하는" 결함이 존재했다. (이런 문제가 계속 발생하다 보니 v9가 등장하게 된 거다.)

8. v7 → v8 — 불확실성 자체의 모델링

임시정부 소속 4건 개별 재검증: 이동휘 1919-09±2개월(재검색으로 범위 조정), 이승만 1919-09-11 확정, 이동녕·이시영은 간접인용 상태로 미재확인 표시(사용자가 제공한 한국민족문화대백과사전 인용을 채택했으나 원문 URL을 직접 재확인하지 못했음을 정직하게 남김). 이종일-보성사 구조 분리(:보성사 Group 신설, v7의 결함 해소), hasValidationStatus 신설 (김좌진-신민회를 "검증보류"로 격리 — 원 논문에 없던 속성을 즉석에서 추가한 것), 신흥강습소/신흥무관학교 실체 분리(개칭 이벤트 존재 자체의 불확실성 모델링).

v8이 P1(다음 라운드 우선순위)로 명시적으로 이월한 것: 홍범도 전투참여 Month 단위 보강, 북로군정서 김좌진/서일 역할 비대칭(총재 vs 사령관) 반영, 천도교 소속 3건(손병희·오세창·최린) 재검색, 안명근-안악사건 "참여" 관계와 기존 체포/확대 이벤트 체인 간 의미 중복 정리. 이 중 안명근-안악사건 문제는 §III의 "사후 발견"에서 보듯 v9.4까지 이어지며 형태를 바꿔 재등장한다 — v8이 "P1"로 미뤄둔 이 항목이 실제로는 다음 트랙(Provenance)에서도 완전히 해소되지 못한 채 이어졌다는 뜻이고, 애초에 이래서 병렬 트랙이라고 말하는 거다.

III. Provenance 트랙 상세 (ver2 ~ v9.5)

v8을 검증하는 별도 트랙. v8의 다음 버전이 아니다.

  • ver2~ver5(방법론 설계) — URL 팩트체크(ver2) → Claim/Evidence/Source 분리(ver3) → 김좌진 정정·Claim 분해 (ver4) → 설계 승인, Rule G-01~G-08 확정(ver5). ver2 단계에서 「이승훈」 항목 원문을 직접 열어보니 "11월 24일"로 되어 있어, v6이 "복수 출처 일치"로 확정했던 "12월 24일"의 근거 자체가 두 계열 출처를 짜깁기한 것이었음이 드러남.
  • v9 초안~완성본 — 49개 항목 → 43개 행(오판 6개 UNMAPPED) → 원본 마스터리스트 대조로 진짜 누락 3건(신흥무관학교· 대한독립군·양기탁) 복원 → 55개 Claim 완성(커버리지 확보, 아직 신뢰도 필터링 전).
  • v9.1 — 구조 검증. CLM-023(SRC 오배정)·CLM-010(비표준 precision) 수정, TTL 1155 트리플.
  • v9.2 — 39개 포함(당시 "High-confidence"로 잘못 명명) + 16 exclusion 최초 분리. 재검증 중 CLM-006 컬럼 밀림·CLM-023 재발·CLM-010 재발·안악사건(item 15) 완전 누락 발견·수정. TTL 928 트리플.
  • v9.3 — 39개를 34 Core + 5 Hold로 재분류, 4단계 판정 (유지/수정/보류/제외) 확정. CLM-023이 또 재누락된 것을 "개별 버그가 아니라 파이프라인 재현성 문제"로 격상. TTL 969 트리플.
  • v9.4 — Claim 문장·URI·relation 의미 정합성 6건 수정 (CLM-014 subject 오류, CLM-003 방향 불일치 등). not_applicable vocab 신설. TTL 972 트리플.
  • v9.5 — date_status 완전 정합화(빈 값 0건). 1차 제안 규칙("date_value 없음→전부 not_applicable")이 자기모순임을 재검토에서 발견해 폐기, "Claim의 시간적 의미" 기준으로 재수립 (not_applicable 9건/not_directly_verified 6건). TTL 987 트리플, Core 34 + Hold 5 + Exclusion 16 = 55.
  • 사후 발견(3자 비교분석에서) — CLM-014가 "안악사건→105인사건" 인과관계를 이미 담고 있으나 relation=related_to라는 범용 값이라 단순연관과 구분 못 하고, "안명근체포→안악사건" 전반부는 v9.4에서 "안명근" 엔티티 자체가 39건 중 하나도 안 남게 되며 유실됐음이 뒤늦게 규명됨 — 모델의 한계가 아니라 relation 어휘 미비 + 데이터 이관 유실이 겹친 문제.

IV. 시각화 트랙 상세 (v6 ~ v10, dh-webpage)

  • v6.html — TTL을 fetch로 읽어 GIS+관계망 2탭으로 렌더링. ttl-parser.js로 Event를 두 개의 간선 (hasPreObject→hasObject, hasObject→hasPostObject) 으로 "접어" 표시.
  • v6_with_gonghun.html — 관계망 탭에 v1 스타일 필터·검색 UI 이식 + 공훈전자사료관 연동 최초 시도(당시 필드명 버그로 0명 매칭 — 이 버그는 이후 v8_with_gonghun.html 에도 그대로 계승됐다가 v10에서야 발견·수정됨).
  • v8_d3style.html/v8_with_gonghun.html — v1의 D3 코드 자산을 v8 데이터로 재현. 이 과정에서 버그 3건 (숨은 탭 초기화, CSS grid 높이, versions-data.js 스키마 사고) 발견·수정.
  • v9_5.html — Provenance 트랙 최초 뷰어. claimDecision(core 실선/hold 점선)으로 신뢰도 구분.
  • v9_5re.html — 데이터는 v9_5.html과 완전히 동일, SEMANTIC_REVIEW 참조표(CLM-024· CLM-027-04 2건)로 "의미론 재검토 권고" 표시축만 추가. diff 기준으로도 데이터 fetch·파싱 로직은 0줄 변경 확인.
  • v10.html + gonghun_match.py — 공훈전자사료관 오픈API 연동 탭 추가. 필드명 오류(성명→ NAME_KO) 수정 → HTTP-only API와 HTTPS 배포 간 mixed content 차단(구조적, 미해결) → 공식 문서상 nameKo 파라미터가 실제로는 서버에서 무시됨을 실측 확인 → 브라우저 호출을 포기하고 gonghun_match.py (로컬 실행 스크립트)로 전체 순회(약 382페이지) 방식 전환 → 순회 중 서버 XML 자체의 명세 위반으로 파싱 재중단(139/382페이지 지점)까지, 실패 원인이 바뀔 때마다 갱신 기록. 현재도 미해결.

V. 결론

세 트랙(본체/Provenance/시각화) 모두 같은 데이터를 다루지만 목적이 다르다 — 본체는 "사건을 어떻게 표현할까", Provenance는 "그 표현이 실제로 검증됐는가", 시각화는 "그걸 어떻게 보여줄까"에 답한다. 매 단계마다 "고쳤다고 생각한 문제가 재발하는" 패턴 (오산학교 개교일, CLM-023 3연속 재발, 공훈 API 시행착오)이 반복됐고, 이는 개별 실수가 아니라 검증 없이 결정만 내리고 실제 파일에는 반영하지 않는 작업 방식 자체의 위험을 의미한다. 이런 점 때문에 v9 검증 트랙이 나온 거다.
