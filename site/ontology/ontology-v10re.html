# 자동검사와 인간 검증의 결합: 웹 에이전트 시대의 지식그래프 검증 MOCKUP (아. 글 온톨로지 저장소의 v9_5 자동검사 서술과 비교한 다음 내가 미리 쓴 보고서와 내용 정합성 확인하고, 그 다음 최종본 commit해야 함.) ## 1. 자동검사의 의미 그동안 연구 과정에서 ‘자동검사’, ‘재검증’, ‘재검사’라는 표현을 사용해 왔다. 그러나 이를 검증자의 판단 자체를 기계가 대신하는 것으로 이해하는 것은 적절하지 않다. 이번 검증 MOCKUP을 설계하는 과정에서 자동검사의 의미를 보다 구체적으로 정리할 수 있었다. ## 13. 웹 에이전트 시대에 필요한 것은 자동판정보다 workflow의 설계 이러한 관점에서 웹 에이전트와 이번 MOCKUP의 관계를 다음과 같이 정리할 수 있다. ```text 검증 의도 ↓ 명시적 규칙 정의 ↓ SPARQL / Script 등 실행 가능한 규칙 ↓ 그래프 데이터 탐색 ↓ 검토 후보 탐지 ↓ 관련 Claim·Source 비교 ↓ 인간의 의미 판단 ↓ 판정 근거 기록 ``` 현재 MOCKUP은 이 전체 과정 중 모든 단계를 실제 자동화한 시스템은 아니다. 실제 SPARQL 실행이나 외부 자료 검색, 데이터 갱신, 영구 저장, LLM에 의한 의미 판단 기능은 구현하지 않았다. 그러나 **탐지 → 비교 → 인간 판정 → 권고 기록**이라는 workflow를 화면 구조로 구체화했다는 점에서, 향후 웹 에이전트가 여러 데이터와 도구를 연결하여 검증 작업을 지원하는 구조를 설계하는 기초 단계로 볼 수 있다. 특히 중요한 점은 에이전트가 최종적인 역사적 판단을 무조건 대신하는 방향이 아니라는 것이다. 에이전트는 그래프와 자료를 탐색하고, 명확한 규칙을 실행하며, 관련 후보를 모으고, 사람이 판단해야 하는 지점을 제시할 수 있다. 최종적으로 의미와 맥락에 대한 판단이 필요한 부분은 인간 검토자가 확인하도록 설계할 수 있다. --- ## 14. MOCKUP이 보여주는 자동화의 범위 이번 작업을 통해 자동화할 수 있는 영역과 인간 판단으로 남겨야 하는 영역을 구분할 수 있었다. | 영역 | 자동화 가능성 | MOCKUP의 대응 | | ----------------------------- | ----------- | -------------- | | 특정 속성 존재 여부 | 높음 | 구조적 규칙으로 표현 가능 | | 동일 Subject·Object·Relation 탐지 | 높음 | Rule B | | 관계 유형 차이 탐지 | 높음 | Rule A | | Claim 후보 간 구조 비교 | 높음 | 대조 화면 | | 같은 사건인지 여부 | 제한적 | Stage 1 인간 판단 | | 출처 내용의 양립 여부 | 제한적 | Stage 2 인간 판단 | | 중복 Claim 병합 여부 | 제한적 | 병합 권고/유보 | | changeHistory의 의미 해석 | 제한적 | 인간 검토 대상 | | 실제 Claim 상태 변경 | 별도 권한·절차 필요 | MOCKUP에서는 미구현 | 따라서 자동화의 목표는 모든 검증을 기계가 수행하는 것이 아니라, **기계가 잘할 수 있는 구조적 탐지와 사람이 해야 하는 의미적 판단을 분리하는 것**이다. ---
