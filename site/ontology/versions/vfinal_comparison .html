Bio CRM · 김바로 교수 초기 Event 모델 · 자체 Provenance 트랙
비교 분석

온톨로지 데이터를 새로 쌓아 올린 버전이 아니라, 그 데이터가 어떤 모델을 참고해 설계되었는지를 정리한 방법론 문서다. Bio CRM 원문의 설계 원칙, 저자가 직접 밝힌 설계 의도, 그리고 실제 TTL·CSV에서 확인한 사실을 구분해가며 세 갈래(메인 온톨로지 · Provenance 트랙 · 2026년 연구계획)의 관계를 정리했다.

Bio CRM 메인 Event 온톨로지 (v1~v8) Provenance 트랙 (v9.x) 2026년 연구계획

0. 설계 의도 원문

논리 전개 본인, 시각화는 클로드

저자 설계 의도 원문 · 그대로 인용, 수정 없음

이 프로젝트는 Bio CRM을 전면적으로 구현하는 것을 목표로 하지 않았다. Bio CRM이 단항 역할, 지속적인 이항 관계, 사건 및 사건 참여자의 역할을 구분하여 인물 정보를 구조화한다는 점을 참고하되, 프로젝트의 자료 특성과 구축 범위에 맞춰 모델의 복잡성을 조절하고자 하였다.

이에 따라 메인 온톨로지의 기본 틀은 김바로 교수의 초기 Event 모델을 채택하였다. 인물의 주요 활동과 사건을 Event 단위로 구조화하고, 프로젝트에서 다루는 관계와 자료의 특성에 맞춰 필요한 요소를 선택적으로 구성하였다. 이는 Bio CRM의 역할 계층과 관계 표현을 모두 도입하기보다, 연구 대상 데이터에 필요한 표현 구조를 우선하는 설계 결정이었다.

또한 본 프로젝트의 자료에는 사건의 발생 시점이나 인물 간 관계를 확정하기 어려운 사례가 포함되어 있었다. 이러한 불확실성을 Event 모델 내부의 구조만으로 일괄 처리하기보다는, 기존 Event 온톨로지와 구별되는 Provenance 트랙을 마련하여 Claim, Evidence, Source를 중심으로 주장과 근거를 추적하도록 구성하였다. 이 트랙에서는 주장의 검증 상태와 판단을 구분해 관리함으로써, 사실 관계를 표현하는 모델과 그 사실 관계를 뒷받침하는 근거를 검토하는 작업을 분리하고자 하였다.

따라서 메인 Event 온톨로지와 Provenance 트랙은 하나의 버전 계열로 이어지는 동일 모델이 아니라, 서로 다른 목적을 수행하도록 구성된 두 설계 축이다. 전자는 인물·사건 및 관계를 구조화하고, 후자는 해당 관계 주장에 대한 근거와 검증 판단을 추적한다. 이와 같은 분리는 자료의 불확실성을 무리하게 확정하지 않으면서도, 연구 데이터의 구조화와 검증 과정을 함께 다루기 위한 선택이었다.

김바로 교수의 2026년 연구계획은 이러한 설계와 비교할 수 있는 후속 연구 맥락으로 참고할 수 있다. 특히 메타데이터, 출처와 신뢰성, 지식 그래프와 LLM 연계에 관한 문제의식은 본 프로젝트의 검증·출처 관리 방향과 비교 지점을 제공한다. 다만 이를 본 프로젝트가 해당 연구계획을 구현했거나 그로부터 직접 영향을 받았다는 의미로 해석하지는 않는다.

1. 분석 범위와 전제

이 비교는 Bio CRM 원문(Tuominen, Hyvönen, & Leskinen, 2018)의 설계 원칙과, 위 저자 설계 의도, 그리고 v9.x Claim/Evidence 기록을 기준으로 한다.

Bio CRM은 전기 정보를 어떤 지식 구조로 표현할지 설계한 CIDOC CRM의 도메인 특화 확장(domain specific extension of CIDOC CRM)이다. 원문은 이를 핵심 설계 원칙(Core Design Principles) 첫 항목으로 명시한다.

표준 어휘 재사용 여부에 대한 확인 범위. v9.x Provenance 트랙과 메인 Event 온톨로지(v1~v8) v8.ttl 모두 실제 TTL 원문을 rdflib로 직접 파싱해 확인했다. 두 파일 어디에도 bioc:나 cidoc: 접두사·프로퍼티가 전혀 선언·사용되지 않았음(0건)을 확인했다. v8.ttl의 owl:Class 5개 전체(System/Term/Event/Group/Person)를 열거해 대조한 결과도 Bio CRM의 Role 계열 클래스에 대응하는 클래스가 하나도 없음을 확인했다.

비교는 다음을 나누어 살펴본다: 표현하려는 지식의 단위와 구조 · 사건·인물·조직 관계의 모델링 방식 · 시간 정보의 처리 · 불확실성·근거·검증 상태의 관리 · 질의·추론·재사용을 위한 구조 · Provenance 트랙이 역할 계층을 채택하지 않은 것의 정확한 의미. 비교 결과는 원문에 명시된 내용, 저자 설계 의도에 명시된 내용, 실제 TTL/CSV 기록에 명시된 내용, 그리고 이들을 대조해 도출한 분석적 해석을 구분해 제시한다.

2. 1차 비교 — Bio CRM ↔ 메인 Event 온톨로지 (v1~v8)

§0 설계 의도에 따르면 Bio CRM이 실제로 참고된 지점

메인 온톨로지는 "김바로 교수의 초기 Event 모델"을 기본 틀로 채택했고, Bio CRM은 그 위에 "단항 역할, 지속적인 이항 관계, 사건 및 사건 참여자의 역할을 구분"한다는 개념만 선택적으로 참고됐다.

표 2-1 · v8.ttl rdflib 직접 파싱 결과 반영
비교 항목Bio CRM 문서의 설계메인 Event 온톨로지(v1~v8)비교 분석
사건 표현 Event가 시간·장소·참여자·참여 역할(Role 인스턴스)을 연결 :Event(74건)가 hasObject(69회)/hasPreObject(5회)/hasPostObject(68회)/hasEventType(69회)/hasTimeValue(43회)를 직접 속성으로 가짐 사건을 1급 개체로 삼는다는 점은 같으나, Bio CRM처럼 참여자를 별도 Role 인스턴스로 매개하지 않고 Event가 관계 대상을 속성으로 직접 참조한다
속성·관계·사건 3분법 명시적 설계 원칙 — "주교였다"가 사건인가 같은 경계 사례를 원문이 직접 제시 owl:Class 5개 어디에도 이 3분법을 명시하는 클래스·주석 없음(직접 확인) 사건과 정적 관계를 구분해야 한다는 문제의식 일부는 공유할 수 있으나, Bio CRM 수준의 명시적 경계 규칙까지는 도입되지 않았다
역할(Role) 계층 Entity_Role 아래 Actor_Role/Thing_Role, Actor_Role 아래 다시 Unary_Role/Binary_Relationship_Role/Event_Role 세 유형 역할 클래스 없음 — owl:Class 5개(System/Term/Event/Group/Person) 전수 확인, 대응 클래스 0건 메인 온톨로지가 채택하지 않은 것이 정확히 이 부분이다 — §0이 "필요한 요소를 선택적으로 구성"했다고 밝힌 지점과 정확히 일치
시간 표현 TimeSpan 인스턴스 + P4_has_timespan으로 시간적 맥락화 hasTimeValue 리터럴 직접 부여(43회), hasEestimation("오타 포함 표기", 43회 확인)으로 추정 여부만 표시 시간을 사건에 결부하는 큰 틀은 같으나, TimeSpan을 재사용 가능한 개체로 분리하지 않고 리터럴로 직접 기록한다
CIDOC-CRM 어휘 재사용 bioc:가 cidoc:E5_Event, E21_Person 등을 직접 서브클래싱 없음 — 파일 전체 검색 결과 bioc:/cidoc: 0건, 독자 네임스페이스만 사용 개념 참고는 있으나, 표준 어휘 상속은 메인 온톨로지에도 전혀 없음이 직접 확인됐다

2-1. 메인 온톨로지와 Bio CRM의 개념적 접점

저자 설계 의도에 따르면 메인 Event 온톨로지는 김바로 교수의 초기 Event 모델을 기본 틀로 채택하고, Bio CRM의 개념을 자료 특성과 구축 범위에 맞춰 선택적으로 참고하였다. v8.ttl 직접 대조 결과, 이 접점은 "Event를 1급 클래스로 삼는다"는 수준에 그친다 — Bio CRM의 역할 계층, TimeSpan 분리, CIDOC-CRM 서브클래싱은 어느 것도 채택되지 않았음이 직접 확인됐다. 이는 §0이 명시한 "필요한 요소를 선택적으로 구성"한 결과와 정확히 일치한다.

3. 2차 비교 — Bio CRM ↔ Provenance 트랙 (v9.x)

애초에 두 체계가 답하려는 질문이 다르다는 것을 확인하는 절

§0에 따르면 Provenance 트랙은 Bio CRM을 겨냥해 설계된 것이 아니다. "기존 Event 온톨로지와 구별되는" 별도 목적(주장과 근거의 검증)을 위해 신설된 축이다.

표 3-1 · CSV 필드명 / TTL 속성명 병기
비교 항목Bio CRM 문서의 설계v9.x Provenance 트랙비교 분석
다루는 질문 전기 정보를 어떤 의미 구조로 표현할 것인가 개별 주장을 어떤 근거·상태로 관리하고, 어느 주장을 그래프에 포함할 것인가 같은 도메인(인물사)을 다루지만 질문의 층위 자체가 다르다
기본 지식 단위 Person, Actor, Group, Event, Role, Relationship 등 도메인 클래스로 전기 정보를 의미 구조로 표현 Claim(CSV: subject_uri/relation/object_uri/claim; TTL: prov:hasSubject/prov:hasRelation/prov:hasObject) + Evidence + Source Bio CRM은 전기 정보를 의미 구조로 표현하는 모델, v9.x는 개별 주장과 근거·검증 상태를 관리하는 트랙이다
역할 모델링 Entity_Role 아래 세 역할 유형 + Thing_Role로 참여자·자격을 구조화 역할 클래스 없음. Claim의 구조화된 필드와 주장 문장을 대조하는 등, v9.x에서 정의한 검토 규칙을 적용 v9.x는 역할 계층을 동일한 방식으로 모델링하는 대신 주장과 근거의 추적·검토에 초점을 둔다
불확실성 관리 원문 발췌 범위에서는 reasoning 기반 enrichment 언급 수준 CSV: claim_status/verification_status/date_status/review_flag; TTL: prov:hasClaimStatus 등으로 다축 관리, core/hold/exclusion으로 수록 여부 관리 이 부분이 Provenance 트랙이 실제로 풀려고 만들어진 문제다 — Bio CRM 발췌문에는 대응 체계가 제시되어 있지 않다
시간 정보 Event에 TimeSpan을 부여해 "언제 일어났는가"를 표현 CSV: date_status; TTL: prov:hasDateStatus — 날짜 확인 여부를 표현. Rule G-02로 사건일→개인 참여일 자동상속 금지 시간 자체를 표현하는 문제와 날짜 주장의 검증 상태를 기록하는 문제 사이의 차이. Bio CRM의 의미적 검증·보강 기능 전반을 부정하는 것은 아니다
복잡성에 대한 태도 역할 계층으로 속성 수를 줄이고 재사용성·질의 편의성을 높이려 함 22개 CSV 컬럼 고정, relation vocabulary 정규화·SHACL·파이프라인 개편은 후속 과제로 유보 Bio CRM은 표현 체계를 정교화해 복잡성을 관리하고, v9.x는 현재 범위를 제한해 운영 부담을 통제한다

3-1. "제외"가 아니라 "관할이 다름" — "완전히 별도"의 의미 한정

Provenance 트랙은 메인 Event 온톨로지의 후속 버전으로서 동일한 모델을 확장한 것이 아니라, 주장과 근거 및 검증 판단을 다루기 위해 별도로 구성된 설계 축이다. Bio CRM의 역할 계층을 채택하지 않았다는 사실을 곧바로 역할 모델의 누락이나 불완전한 구현으로 해석해서는 안 된다. 두 트랙은 설계 목적과 표현 단위가 구별되지만, 프로젝트 안에서는 인물·사건·관계에 관한 지식의 구조화와 그 지식에 대한 근거 검토라는 상호 보완적 기능을 수행한다.

피할 표현 Bio CRM식 구조를 그대로 적용하면 복잡해지기 때문에 일부러 제외했다 / 완전히 별도의(= 개념적으로도 무관한) 설계 축이다
권장 표현 목적과 모델 구조가 구별되는 별도 설계 축이며, 프로젝트 차원에서는 상호 보완 관계를 가진다

3-2. 그럼에도 남는 개념적 접점

  • Rule G-02는 사건의 날짜를 개인의 참여 날짜로 자동 상속하지 않도록 하는 검토 규칙이다. Bio CRM 역시 사건과 역할을 시간적 맥락 속에서 표현할 수 있으므로 시간 정보의 맥락화라는 점에서 비교할 수 있다. 다만 두 규칙이 동일하다는 뜻은 아니다.
  • not_applicable/not_directly_verified/verified는 v9.x에서 날짜 주장의 적용 여부와 확인 상태를 구분하기 위한 분류다. 이번에 검토한 Bio CRM 문헌 범위에서는 이와 동일한 Claim 단위 분류 체계를 확인하지 못했다.

세 문서는 인물 정보의 구조화라는 넓은 주제에서 비교할 수 있지만, 문서의 성격과 기술 범위는 서로 다르다. 비교 결과는 주제적 접점과 구조적 차이를 보여주는 분석으로 제시하고, 직접 계승·영향·구현 여부는 별도의 문서 이력이나 코드 근거가 있을 때만 주장한다.

5. 종합 판단

  1. Bio CRM은 인물·사건·역할을 일관되게 표현하기 위한 CIDOC-CRM 확장 모델을 제시한다.
  2. 메인 Event 온톨로지(v1~v8)는 김바로 교수의 초기 Event 모델을 기본 틀로 삼되, Bio CRM의 역할 계층·이항 관계 구분을 필요한 범위에서만 선택적으로 참고했다.
  3. Provenance 트랙(v9.x)은 메인 온톨로지의 "다음 버전"이 아니라, 자료의 불확실성을 Event 모델 내부로 흡수하지 않기 위해 신설된, 목적과 모델 구조가 구별되는 별도의 설계 축이며, Bio CRM의 역할 계층과는 애초에 관할하는 문제가 다르다. 다만 동일 프로젝트 안에서 메인 온톨로지와는 상호 보완 관계에 있다.
  4. 2026년 연구계획은 이 두 축(구조화·검증)이 다뤄온 문제의식을 Graph RAG/KAG·LLM 연계까지 확장한 것과 비교 가능한 연구 맥락으로 참고할 수 있으나, 직접적 계승·구현 관계는 확인되지 않는다.
