\01\ \

탐지 계층 — 분류 대기 Claim 목록\

\탐지 규칙 예시(의사코드) · 실제 배치 잡 미연결\ \
\
아래 목록은 "둘 중 하나가 틀렸다"는 상충(conflict) 목록이 아니라, \서로 다른 종류의 관계를 갖는 Claim 쌍\이 발견됐으니 사람이 그 관계의 성격을 확정해 달라는 목록이다. \hasReviewFlag\(문제 신호)와 \claimDecision\ (core/hold 처리 결과)은 이미 v9.3에서 끝난 판정이며, 이 화면은 그 판정을 뒤집는 곳이 아니라 \왜 그 판정을 유지·승격하는지 근거를 추가\하는 곳이다. 성격이 다른 두 종류의 탐지 규칙(A/B)이 있고, 각 규칙은 서로 다른 처리 버튼 세트로 이어진다. \
\
\ \
\
\
# 규칙 A — 같은 item에 서로 다른 relation을 가진 Claim이 존재 (관계 유형 상이 탐지)\
\
PREFIX prov: <[https://ontology.gwanhak-inmul.kr/prov#>](https://ontology.gwanhak-inmul.kr/prov#\>); SELECT ?item ?c1 ?r1 ?c2 ?r2 WHERE { ?c1 prov\:belongsToItem ?item ; prov\:hasRelation ?r1 . ?c2 prov\:belongsToItem ?item ; prov\:hasRelation ?r2 . FILTER(?c1 != ?c2 && ?r1 != ?r2) }\
\
# 규칙 B — 같은 subject·object·relation을 가진 서로 다른 claim_id (동일 주장 중복 서술 탐지, item 무관)\
\
PREFIX prov: <[https://ontology.gwanhak-inmul.kr/prov#>](https://ontology.gwanhak-inmul.kr/prov#\>); SELECT ?c1 ?c2 WHERE { ?c1 prov\:hasSubject ?s ; prov\:hasObject ?o ; prov\:hasRelation ?r . ?c2 prov\:hasSubject ?s ; prov\:hasObject ?o ; prov\:hasRelation ?r . FILTER(?c1 != ?c2) }\
\
※ 위 두 쿼리는 실제로 실행해 결과를 얻은 것이 아니라, 아래 목록이 어떤 규칙으로 나왔을지를 보여주는 의사코드다. 규칙 B는 \belongsToItem\을 조건에 넣지 않으므로, 아래 대성학교 사례처럼 서로 다른 item(item-2, item-21)에 속한 Claim끼리도 탐지할 수 있다 — 규칙 A(같은 item 안에서만 비교)와는 범위가 다르다. \
