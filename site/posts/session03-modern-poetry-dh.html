근대시, 알고리즘으로 다시 읽기

참고한 세션 진행자: 박선영 세션 일시: 2026-08-20 (목)
#근대시 #김소월 #감정분석 #KPoEM
ℹ️ 이 글은 실제 세션에 참석한 기록이 아닙니다. 한국학중앙연구원 디지털인문학연구소가 공개한 "텍스트와 사료의 데이터화" 워크숍 세션 소개 내용을 바탕으로, 같은 주제를 제가 구현해본 기록입니다.

"[Day 2] 텍스트와 사료의 데이터화" 워크숍 Session 03은 현대시 텍스트를 알고리즘적으로 분석하는 주제를 다룬다고 소개되어 있었다. 이 글은 그 소개 내용을 참고하여, 같은 문제를 어떻게 풀어볼 수 있을지 직접 구현해본 기록이다. (자세한 코드 내역은 sowol_poem_analysis 저장소에서 확인해 주세요.)

다만 대상 텍스트는 세션 소개의 "현대시" 대신, 근대시로 바꿔서 구현했다. 김소월 시집 『진달래꽃』 중 "바다가 변하야 뽕나무밭 된다고" 섹션에 실린 9편 (불운에 우는 그대여, 바다가 변하야 뽕나무밭 된다고, 황촉불, 맘에 있는 말이라고 다 할까 보냐, 훗길, 부부, 나의 집, 새벽, 구름)이 그 대상이다. 감정 분석 모델은 한국학중앙연구원 디지털인문학연구소(AKS-DHLAB)가 한국 근현대시에 특화해 공개한 KPoEM(Korean Poetry Emotion Mapping)을 사용했다.

왜 시를 "계산"하는가

문학 텍스트, 특히 시는 오랫동안 정성적 해석의 영역으로 여겨져 왔다. 하지만 시어의 반복, 리듬, 어휘 선택의 패턴은 통계적으로도 유의미하게 관찰될 수 있다. 세션에서 제시된 문제의식은 결국 "정량적 분석이 정성적 해석을 대체하는가"가 아니라, "정량적 분석이 어떤 질문을 새로 던지게 하는가"에 가까웠다. 이러한 질문은 디지털 인문학에서 꼭 필요한 것이라고 생각하며, 이번 분석에서도 질문을 중심으로 논지를 전개했다.

세션 소개에서 유추한 접근 축

  • 어휘·형태소 빈도 기반의 시대·시인별 문체 비교
  • 행간 유사도 측정을 통한 이미지 계열(자연, 도시, 신체 등) 군집화
  • 텍스트를 벡터 공간에 투영해 시인 간 거리·근접성을 시각화하는 방식
이 주제를 직접 구현해보며 정리한 관점은 다음과 같다. 숫자로 표현된 시는 "시가 아닌 것"이 되는 게 아니라, 시를 읽는 '또 하나의 렌즈'가 된다.

제가 구현한 것

"텍스트를 벡터 공간에 투영해 거리·근접성을 시각화"한다는 접근 축을, 임베딩 기반 UMAP/t-SNE 대신 KPoEM의 감정 라벨별 예측값 벡터로 구현. 감정 라벨 자체가 이미 해석 가능한 축이라, 별도의 차원 축소 없이도 시별 감정 분포를 히트맵으로 비교할 수 있다는 게 이 접근의 장점이었다. 다만 현재 구현은 작품 사이의 거리값을 별도로 계산하지 않고, 감정값의 분포를 색으로 비교한다. (참고> 별도 계산 경우 아마 해보신 분들은 아시겠지만, 로직이 더 복잡해서 구현하는 데 시간이 오래 걸리며, 전제와 결론 사이의 정합성을 논리 있게 서술하는 게 어렵습니다.)

1> 대상 자료 — 근대시를 고른 이유

김소월(1902~1934)은 세상을 뜬 지 70년이 훨씬 지나, 저작권법상 보호기간(저작자 사후 70년)이 끝난 퍼블릭 도메인 저자다. 그래서 진달래꽃』 9편 원문을 코드 저장소에 그대로 담아 공개해도 저작권 문제가 없다는 실용적인 이유로 근대시를 선택했다. (이전에 다룬 효경언해 OCR 프로젝트에서는 반대로, 근대 역주 저작물의 저작권 때문에 정답 텍스트를 저장소에 넣지 못했던 경험이 있다. 같은 "텍스트를 다루는 작업"이라도 시기와 저작권 상태에 따라 접근이 완전히 달라진다는걸 두 프로젝트를 나란히 해보며 체감했다.)

2> 모델 — KPoEM

KPoEM은 KcELECTRA-base를 범용 감정 데이터셋 KOTE로 1차 파인튜닝한 뒤, 한국 근현대시 감정 라벨링 데이터셋인 KPoEM으로 2차(도메인 특화) 파인튜닝한 모델이다. 감정 라벨(슬픔, 서러움, 안타까움/실망, 비장함 등)에 대해 다중 라벨(multi-label) 예측값을 반환한다. 감정 라벨은 총 44개이며, 인덱스는 0부터 43까지 부여된다. 모델 카드에 공식으로 안내된 사용 코드(가중치 로드 방식, 라벨 순서)를 그대로 따라 래퍼 클래스를 만들었다. 라벨 순서를 임의로 바꾸면 분류 결과 자체가 어긋나는 구조라, 이 부분만큼은 그대로 가져다 썼다.

3> 분석 단위 — 시 전체 vs 행 단위

시 한 편을 통째로 모델에 넣으면 512 토큰 제한 안에서 여러 정서가 뭉뚱그려질 수 있다고 판단해, 시 전체 단위와 행 단위를 모두 분석해 결과에 같이 담았다. 예> "황촉불" 같은 짧은 시는 시 전체로 봐도 정서가 비교적 뚜렷하게 드러나지만, 여러 정서가 교차하는 긴 시(예: "맘에 있는 말이라고 다할까 보냐")는 행 단위로 쪼개 볼 때와 시 전체로 볼 때 상위 감정 구성이 달라질 여지가 있었다. 어느 단위가 "옳은" 분석 단위인지는 정해진 답이 없고, 이건 아래 "구현하며 남은 질문"으로 그대로 이어진다.

4> 구조화 및 시각화

분석 결과는 단순 수치 나열이 아니라 { title, lines: [{line_no, text, emotions}], poem_level_emotions } 형태의 구조화된 JSON으로 저장했다. 그 위에 두 가지 시각화를 얹었다.

  • 히트맵: 9편 × 상위 감정(시집 전체 평균값 기준 상위 12개)을 한 화면에 놓고, 작품별 감정 분포를 색 농도로 비교할 수 있게 했다.
  • 시별 top-5 막대그래프: 각 시를 대표하는 상위 5개 감정을 개별 그래프로 뽑아, 히트맵에서는 잘 안 보이는 개별 시의 정서 구성을 자세히 볼 수 있게 했다.

5> 실행 결과 — 히트맵에서 읽히는 것

실제로 파이프라인을 돌려보니, 9편 대부분(1, 2, 3, 4, 7, 8, 9번)은 슬픔·서러움·안타까움/실망·불안/걱정 네 감정이 진한 빨강(확률 0.9 안팎)으로 공통적으로 깔렸다. 김소월 특유의 애상적 정조를 생각하면 그 자체로는 새삼스러운 결과가 아니다.

흥미로웠던 부분> 5번 "훗길"과 6번 "부부"만 이 패턴에서 벗어났다. 나머지 7편이 슬픔 계열로 진하게 물든 것과 달리, "훗길"의 상위 감정은 깨달음·아껴주는·비장함·기대감·감동/감탄이고, "부부"는 비장함이 1위, 그 뒤를 깨달음·기대감·슬픔·안타까움/실망이 잇는다. 텍스트를 다시 읽어보면 이 둘은 부모 자식 간의 되풀이되는 마음을 관찰하는 시("훗길")와 부부의 연을 다짐하는 시("부부")로, 나머지 7편의 실연·이별 정조와는 성격이 다른 "선언적/교훈적" 어조의 시다. 정성적으로 읽을 때도 결이 다르다고 느낄 법한 두 편이, 정량 지표에서도 나머지와 뚜렷이 갈라져 나온 셈이다. (그런데 이러한 '정성적' 평가는 어디까지나 필자의 생각일 뿐이며, 사람에 따라 판단은 다를 수 있다.)

막대그래프로 시를 보면, 히트맵에서는 잘 안 보이던 순서 차이도 드러난다. 예를 들어 1번 "불운에 우는 그대여"와 2번 "바다가 변하야 뽕나무밭 된다고"는 둘 다 슬픔·서러움·안타까움/실망이 상위 3개로 같지만, 4·5위 감정이 각각 불쌍함/연민·불안/걱정으로 갈린다. 앞서 "숫자로 표현된 시는 시를 읽는 또 하나의 렌즈가 된다"고 정리했던 관점을, 이 내용을 통해 실제 결과로 확인해본 셈이다.

파이프라인 구조

preprocess.py      # 시 9편 로드 및 텍스트 정제
emotion_model.py    # KPoEM 모델 래퍼 (공식 사용 예시 코드 기반)
analyze.py            # 시 전체/행 단위 분석 -> 구조화된 레코드 변환
visualize.py            # 히트맵 + 시별 top감정 막대그래프
main.py                     # 위 네 단계를 잇는 CLI

전처리 → 레이아웃 분석/인식 → 후처리로 이어졌던 OCR 파이프라인 구조를, 이번에는 로드/정제 → 감정 분류 → 구조화 → 시각화로 그대로 재사용했다. "비정형 텍스트를 다루는 파이프라인"이라는 틀 자체는 사료 OCR이든 근대시 감정 분석이든 크게 다르지 않았다.

구현하며 남은 질문

  • 양적 분석의 단위(행 vs 연 vs 시 전체)를 어떻게 잡느냐에 따라 해석이 달라질 수 있는데, 이 경계를 어떻게 정당화할 것인가?
  • 번역시·구술시처럼 원문의 형태가 유동적인 자료는 같은 파이프라인을 그대로 적용할 수 있는가?
  • KPoEM처럼 특정 시기·장르(한국 근현대시)에 맞춰 파인튜닝된 감정 모델의 결과를, 정성적 해석의 "정답"이 아니라 "새로운 질문을 던지는 자료"로만 쓰려면 어떤 절차적 장치가 필요한가?
  • "훗길"·"부부"가 나머지 7편과 다른 감정 패턴을 보인 것이 정말 정서적 이질성 때문인가? 아니면 단순히 모델이 선언적/교훈적 어조를 서정시와 다르게(오분류에 가깝게) 처리한 결과인가? 사실 위 결과만으로는 이 내용을 구분할 수 없다고 생각하며, 이런 경계 사례를 어떻게 검증할 것인지 고민해 봐야 한다.

향후 보완·확장할 수 있는 부분 [이 내용은 26.09.22 서술]

현재 구현은 시 전체와 행 단위 감정 분석, JSON 구조화, 히트맵 및 시별 상위 감정 그래프를 생성하는 데 초점을 두었고, 현재 결과를 분석의 설명력과 재현성을 높이기 위한 후속 작업 후보로 다음 내용을 생각해 볼 수 있다.

  • 라벨 수와 문서 표기 통일: 래퍼의 라벨 목록과 주석·설명에 적힌 라벨 수를 모델 자료와 대조해 일치시킨다.
  • 거리·유사도 분석의 확장: 작품 사이의 정서적 거리를 실제로 논의하려면 감정 벡터 간 거리 또는 유사도 지표를 별도로 정의하고, 그 계산 방식과 해석 범위를 함께 기록한다.
  • 임계값과 집계 기준 기록: 임계값 설정이 결과에 미치는 영향을 살펴보고, 히트맵의 상위 감정 선정과 집계 기준을 재현 가능한 형태로 문서화한다.
  • 행·연 구조 보존: 현재 행 단위 분석은 빈 행을 제외해 순번을 부여하므로, 연 구분이나 원문 행 번호가 중요한 연구에서는 구조 정보를 별도로 보존하는 방안을 검토한다.
  • 모델 입력과 문맥 검토: 최대 입력 길이와 잘림 여부, 시 전체 입력과 행 단위 입력의 문맥 차이가 결과 해석에 미치는 영향을 확인한다.
  • 재현성 정보 보강: 원문 판본과 출처, 모델 버전, 실행 환경, 라이브러리 버전, 임계값 및 실행 명령을 함께 기록한다.
  • 경계 사례의 정성적 재검토: 훗길」과 「부부」처럼 다른 패턴을 보이는 작품은 원문을 다시 읽고, 모델 출력이 해석에 어떤 질문을 제기하는지 검토한다. (이 내용은 위에서도 다뤄졌는데, 자세히 서술하지 않았기에 여기서도 다시 언급하게 되었다.)

다음 글에서는 Session 04 소개 내용을, 그동안 다뤄본 OCR 파이프라인 구현 경험과 엮어 직접 구현해본 기록을 정리한다. (참고로 OCR 프로젝트에서는 Tesseract를 사용했는데, Tesseract 4.0 이후 버전은 내부적으로 LSTM 신경망 기반 인식 엔진을 기본값으로 쓴다 — 다만 직접 모델을 학습하거나 파인튜닝한 것은 아니고, 이미 학습된 엔진을 그대로 가져다 쓴 것이다. PaddleOCR·TrOCR처럼 직접 손을 더 대볼 수 있는 딥러닝 백엔드는 다음 과제로 남겨두었다.)
