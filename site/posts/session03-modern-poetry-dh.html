근대시, 알고리즘으로 다시 읽기

참고한 세션 진행자: 박선영 세션 일시: 2026-08-20 (목)
#근대시 #김소월 #감정분석 #KPoEM
ℹ️ 이 글은 실제 세션에 참석한 기록이 아닙니다. 한국학중앙연구원 디지털인문학연구소가 공개한 "텍스트와 사료의 데이터화" 워크숍 세션 소개 내용을 바탕으로, 같은 주제를 제 힘으로 직접 구현해본 기록입니다.

"[Day 2] 텍스트와 사료의 데이터화" 워크숍 Session 03은 현대시 텍스트를 알고리즘적으로 분석하는 주제를 다룬다고 소개되어 있었다. 이 글은 그 소개 내용을 실마리 삼아, 같은 문제를 스스로 어떻게 풀어볼 수 있을지 직접 구현해본 기록이다.

다만 대상 텍스트는 세션 소개의 "현대시" 대신, 근대시로 바꿔서 구현했다. 김소월 시집 『진달래꽃』 중 "바다가 변하야 뽕나무밭 된다고" 섹션에 실린 9편(불운에 우는 그대여, 바다가 변하야 뽕나무밭 된다고, 황촉불, 맘에 있는 말이라고 다 할까 보냐, 훗길, 부부, 나의 집, 새벽, 구름)이 그 대상이다. 감정 분석 모델은 한국학중앙연구원 디지털인문학연구소(AKS-DHLAB)가 한국 근현대시에 특화해 공개한 KPoEM(Korean Poetry Emotion Mapping)을 사용했다.

왜 시를 "계산"하는가

문학 텍스트, 특히 시는 오랫동안 정성적 해석의 영역으로 여겨져 왔다. 하지만 시어의 반복, 리듬, 어휘 선택의 패턴은 통계적으로도 유의미하게 관찰될 수 있다. 세션에서 제시된 문제의식은 결국 "정량적 분석이 정성적 해석을 대체하는가"가 아니라, "정량적 분석이 어떤 질문을 새로 던지게 하는가"에 가까웠다.

세션 소개에서 유추한 접근 축

  • 어휘·형태소 빈도 기반의 시대·시인별 문체 비교
  • 행간 유사도 측정을 통한 이미지 계열(자연, 도시, 신체 등) 군집화
  • 텍스트를 벡터 공간에 투영해 시인 간 거리·근접성을 시각화하는 방식
숫자로 표현된 시는 "시가 아닌 것"이 되는 게 아니라, 시를 읽는 또 하나의 렌즈가 된다 — 이 주제를 직접 구현해보며 스스로 정리해본 관점이다.

제가 직접 구현한 것

"텍스트를 벡터 공간에 투영해 거리·근접성을 시각화"한다는 접근 축을, 임베딩 기반 UMAP/t-SNE 대신 KPoEM의 43차원 감정 확률 벡터로 구현해보았다. 감정 라벨 자체가 이미 해석 가능한 축이라, 별도의 차원 축소 없이도 시들 사이의 정서적 근접성을 히트맵으로 바로 읽을 수 있다는 게 이 접근의 장점이었다.

1) 대상 자료 — 근대시를 고른 이유

김소월(1902~1934)은 세상을 뜬 지 70년이 훨씬 지나, 저작권법상 보호기간(저작자 사후 70년)이 끝난 퍼블릭 도메인 저자다. 그래서 『진달래꽃』 9편 원문을 코드 저장소에 그대로 담아 공개해도 저작권 문제가 없다는 실용적인 이유로 근대시를 선택했다. (이전에 다룬 효경언해 OCR 프로젝트에서는 반대로, 근대 역주 저작물의 저작권 때문에 정답 텍스트를 저장소에 넣지 못했던 경험이 있다 — 같은 "텍스트를 다루는 작업"이라도 시기와 저작권 상태에 따라 접근이 완전히 달라진다는 걸 두 프로젝트를 나란히 해보며 체감했다.)

2) 모델 — KPoEM

KPoEM은 KcELECTRA-base를 범용 감정 데이터셋 KOTE로 1차 파인튜닝한 뒤, 한국 근현대시 감정 라벨링 데이터셋인 KPoEM으로 2차(도메인 특화) 파인튜닝한 모델이다. 43개 감정 라벨(슬픔, 서러움, 안타까움/실망, 비장함 등)에 대해 다중 라벨(multi-label) 확률을 반환한다. 모델 카드에 공식으로 안내된 사용 코드(가중치 로드 방식, 라벨 순서)를 그대로 따라 래퍼 클래스를 만들었다 — 라벨 순서를 임의로 바꾸면 분류 결과 자체가 어긋나는 구조라, 이 부분만큼은 그대로 가져다 썼다.

3) 분석 단위 — 시 전체 vs 행 단위

시 한 편을 통째로 모델에 넣으면 512 토큰 제한 안에서 여러 정서가 뭉뚱그려질 수 있다고 판단해, 시 전체 단위와 행 단위를 모두 분석해 결과에 같이 담았다. 예를 들어 "황촉불" 같은 짧은 시는 시 전체로 봐도 정서가 비교적 뚜렷하게 드러나지만, 여러 정서가 교차하는 긴 시(예: "맘에 있는 말이라고 다 할까 보냐")는 행 단위로 쪼개 볼 때와 시 전체로 볼 때 상위 감정 구성이 달라질 여지가 있었다. 어느 단위가 "옳은" 분석 단위인지는 정해진 답이 없고, 이건 아래 "구현하며 남은 질문"으로 그대로 이어진다.

4) 구조화 및 시각화

분석 결과는 단순 수치 나열이 아니라 { title, lines: [{line_no, text, emotions}], poem_level_emotions } 형태의 구조화된 JSON으로 저장했다. 그 위에 두 가지 시각화를 얹었다.

  • 히트맵: 9편 × 상위 감정(시집 전체 평균 확률 기준 상위 12개)을 한 화면에 놓고, 시들 사이의 정서적 근접성을 색 농도로 비교할 수 있게 했다.
  • 시별 top-5 막대그래프: 각 시를 대표하는 상위 5개 감정을 개별 그래프로 뽑아, 히트맵에서는 잘 안 보이는 개별 시의 정서 구성을 자세히 볼 수 있게 했다.

5) 실행 결과 — 히트맵에서 읽히는 것

실제로 파이프라인을 돌려보니, 9편 대부분(1, 2, 3, 4, 7, 8, 9번)은 슬픔·서러움·안타까움/실망·불안/걱정 네 감정이 진한 빨강(확률 0.9 안팎)으로 공통적으로 깔렸다. 김소월 특유의 애상적 정조를 생각하면 그 자체로는 새삼스러운 결과가 아니다.

흥미로웠던 건 5번 "훗길"과 6번 "부부"만 이 패턴에서 벗어난다는 점이다. 나머지 7편이 슬픔 계열로 진하게 물든 것과 달리, "훗길"의 상위 감정은 깨달음·아껴주는·비장함·기대감·감동/감탄이고, "부부"는 비장함이 1위, 그 뒤를 깨달음·기대감·슬픔·안타까움/실망이 잇는다. 텍스트를 다시 읽어보면 이 둘은 부모 자식 간의 되풀이되는 마음을 관찰하는 시("훗길")와 부부의 연을 다짐하는 시("부부")로, 나머지 7편의 실연·이별 정조와는 성격이 다른 "선언적/교훈적" 어조의 시다. 정성적으로 읽을 때도 결이 다르다고 느낄 법한 두 편이, 정량 지표에서도 나머지와 뚜렷이 갈라져 나온 셈이다.

막대그래프로 시 하나하나를 뜯어보면, 히트맵에서는 잘 안 보이던 순서 차이도 드러난다. 예를 들어 1번 "불운에 우는 그대여"와 2번 "바다가 변하야 뽕나무밭 된다고"는 둘 다 슬픔·서러움·안타까움/실망이 상위 3개로 같지만, 4·5위 감정이 각각 불쌍함/연민·불안/걱정으로 갈린다 — "숫자로 표현된 시는 시를 읽는 또 하나의 렌즈가 된다"고 앞서 정리했던 관점을, 이번엔 실제 결과로 확인해본 셈이다.

파이프라인 구조

preprocess.py      # 시 9편 로드 및 텍스트 정제
emotion_model.py    # KPoEM 모델 래퍼 (공식 사용 예시 코드 기반)
analyze.py            # 시 전체/행 단위 분석 -> 구조화된 레코드 변환
visualize.py            # 히트맵 + 시별 top감정 막대그래프
main.py                  # 위 네 단계를 잇는 CLI

전처리 → 레이아웃 분석/인식 → 후처리로 이어졌던 OCR 파이프라인 구조를, 이번에는 로드/정제 → 감정 분류 → 구조화 → 시각화로 그대로 재사용한 셈이다. "비정형 텍스트를 다루는 파이프라인"이라는 틀 자체는 사료 OCR이든 근대시 감정 분석이든 크게 다르지 않았다.

구현하며 남은 질문

  • 양적 분석의 단위(행 vs 연 vs 시 전체)를 어떻게 잡느냐에 따라 해석이 달라질 수 있는데, 이 경계를 어떻게 정당화할 것인가?
  • 번역시·구술시처럼 원문의 형태가 유동적인 자료는 같은 파이프라인을 그대로 적용할 수 있는가?
  • KPoEM처럼 특정 시기·장르(한국 근현대시)에 맞춰 파인튜닝된 감정 모델의 결과를, 정성적 해석의 "정답"이 아니라 "새로운 질문을 던지는 자료"로만 쓰려면 어떤 절차적 장치가 필요한가?
  • "훗길"·"부부"가 나머지 7편과 다른 감정 패턴을 보인 것이 정말 정서적 이질성 때문인지, 아니면 단순히 모델이 선언적/교훈적 어조를 서정시와 다르게(오분류에 가깝게) 처리한 결과인지는 이 결과만으로는 구분할 수 없다. 이런 경계 사례를 어떻게 검증할 것인가?
