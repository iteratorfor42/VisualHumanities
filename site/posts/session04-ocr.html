비정형 사료 OCR이 어려운 이유

일반 문서 OCR과 달리 고문서·필사본 OCR은 다음 지점에서 난도가 크게 올라간다.

  • 활자가 아닌 필사체라 글자 형태의 변이가 크다
  • 세로쓰기, 행간 불규칙, 훼손·얼룩 등 레이아웃이 표준적이지 않다
  • 한자·이두·고어가 섞여 있어 범용 OCR 모델의 어휘 사전과 맞지 않는다

일반적인 파이프라인 구성

워크숍 소개 자료의 문제의식과, 내가 실제로 구성해본 파이프라인을 종합하면 대략 다음 단계로 정리된다.

  1. 전처리: 이진화, 노이즈 제거, 기울기 보정 (OpenCV)
  2. 레이아웃 분석: 문단·행 단위 영역 검출 (예: CRAFT, DBNet 계열의 텍스트 검출 모델)
  3. 문자 인식: 검출된 영역을 CRNN, TrOCR류의 시퀀스 인식 모델에 통과
  4. 후처리: 언어모델 기반 교정, 이체자·이형자 정규화

참고할 만한 오픈소스 도구

  • Tesseract: 범용 OCR, 활자본에는 강하지만 필사체엔 한계가 뚜렷함
  • PaddleOCR: 텍스트 검출+인식 파이프라인이 통합되어 있어 커스텀 데이터로 파인튜닝하기 수월함
  • TrOCR (Transformer 기반): 손글씨 인식에 강점, 한국 고문서 특화 데이터로 파인튜닝 시 성능 향상 여지가 큼
💡 이 주제를 구현하며 스스로 정리한 지점: OCR 정확도 못지않게, 인식된 텍스트를 어떻게 구조화된 데이터(예: 인명·지명·연호 태깅)로 전환할지가 인문학적 활용의 관건이 된다는 것이었다. 단순 텍스트 추출에서 끝나면 "사료의 데이터화"라기보다 "사료의 텍스트화"에 머문다.

내가 실제로 구현해본 것

대상 자료는 세종한글고전 사이트(db.sejongkorea.org)에 공개된 『효경언해』 6ㄴ면 — (고문 제7장) 효평(孝平) 부분이다. 세로쓰기 목판본 한 면을 놓고, 전처리 → 레이아웃 분석/문자 인식 → 후처리로 이어지는 최소 파이프라인을 직접 구성했다. 전체 코드는 GitHub에 MIT 라이선스로 공개해 두었다.

1) 데이터 확보 — 예상 못 한 첫 번째 난관

가장 먼저 부딪힌 문제는 OCR 자체가 아니라 "이미지를 어떻게 가져오느냐"였다. 세종한글고전 사이트는 원본 이미지를 JS 뷰어(확대/축소/내려받기 버튼)로만 서빙하고 있어서, 이미지 URL을 코드로 직접 크롤링할 수 있는 구조가 아니었다. 결국 파이프라인은 "사이트에서 수동으로 내려받은 이미지 한 장을 로컬 경로로 넘겨받는다"는 전제로 설계했다. 실제 데이터화 작업에서는 이렇게 수집 단계 자체가 병목이 되는 경우가 생각보다 많다는 걸 새삼 체감했다.

2) 모델·프레임워크 선택과 파인튜닝 방식

OCR 백엔드는 두 가지를 다 붙여두고 교체 가능하게 짰다.

  • Tesseract(pytesseract)를 주 백엔드로 사용. 시스템에 tesseract-ocr-kor, 한자 언어팩(chi_sim)을 별도 설치해야 했고, Windows에서는 tessdata 폴더에 .traineddata 파일을 직접 받아 넣는 과정이 필요했다.
  • PaddleOCR은 검출+인식이 통합돼 있어 코드상으로는 보조 백엔드로 넣어뒀지만, 실제 로컬 환경(Python 3.14)에서는 호환성 문제로 설치가 되지 않아 requirements.txt에서 주석 처리한 채로 남겨두었다. "이론상 더 나은 도구"와 "지금 내 환경에서 당장 돌아가는 도구"가 다를 수 있다는 걸 확인한 지점.
  • TrOCR 파인튜닝은 이번 구현 범위에는 넣지 못했고, transformers/torch 의존성만 미리 requirements에 올려둔 "다음 단계"로 남겨두었다.

3) 정량 평가(CER/WER) — 구현은 했지만 켜지 않은 이유

CER(문자 오류율)·WER(어절 오류율)을 계산하는 평가 모듈은 만들어 두었다. 세종한글고전 사이트에는 해당 면의 교감된 언해문이 텍스트로 함께 실려 있어서, 이를 정답(ground truth)으로 삼으면 바로 정량 평가가 가능한 구조였다. 그런데 그 교감 텍스트 자체가 세종대왕기념사업회의 역주 저작물이라는 점이 걸렸다. 이를 그대로 로컬 파일로 옮겨 담아 코드 저장소에 두는 것은 저작권 위배 소지가 있다고 판단해서, 이번 구현에서는 의도적으로 평가를 실행하지 않았다. 코드에는 --ground-truth 옵션과 ENABLE_GROUND_TRUTH_EVAL 스위치를 남겨두되 기본값을 꺼둬서, 실제로 저작권 문제가 없는 정답 데이터를 확보한 사람만 의도적으로 코드를 고쳐 켜도록 설계했다. OCR 프로젝트에서는 정확도 자체보다 "정답 데이터를 어떻게 확보하느냐"가 더 먼저 걸리는 문제가 될 수 있다는 걸 배운 부분이다.

4) 이체자·고어 처리를 위한 후처리 로직

후처리 단계는 크게 세 가지로 구성했다.

  • 유니코드 정규화(NFC): 옛한글 자모가 조합형/완성형으로 섞여 인식되는 경우가 있어, 비교·검색이 가능하도록 통일했다.
  • 이체자 매핑 테이블: 원문에서 인식된 이체자 형태를 정자로 치환하는 dict 골격을 만들어 두었다. 지금은 예시 수준이고, 실제 데이터를 더 모으면서 채워나가야 하는 부분.
  • 구조화된 레코드 변환: 인식된 텍스트를 단순 문자열이 아니라 {book, page, chapter, text, entities} 형태의 JSON으로 저장하게 했다. entities에는 인명·지명·연호 등을 태깅할 자리를 미리 비워뒀는데, 이 부분이 앞서 정리했던 "텍스트화에서 데이터화로" 넘어가는 지점과 정확히 맞닿아 있었다.

간단한 전처리 코드 (실제 사용한 버전)

import cv2
import numpy as np

def binarize(gray: np.ndarray) -> np.ndarray:
    # Otsu 이진화
    _, binarized = cv2.threshold(
        gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU
    )
    return binarized

def deskew(img: np.ndarray) -> np.ndarray:
    # 텍스트 영역의 최소 외접 사각형 각도로 기울기 보정
    coords = np.column_stack(np.where(img > 0))
    angle = cv2.minAreaRect(coords)[-1]
    angle = -(90 + angle) if angle < -45 else -angle
    h, w = img.shape[:2]
    M = cv2.getRotationMatrix2D((w // 2, h // 2), angle, 1.0)
    return cv2.warpAffine(img, M, (w, h), flags=cv2.INTER_CUBIC)

def rotate_for_vertical_text(img: np.ndarray) -> np.ndarray:
    # 세로쓰기 원문을 가로쓰기 검출기에 맞게 90도 회전
    return cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)

효경언해는 세로쓰기 목판본이라, 이진화·기울기 보정 다음에 rotate_for_vertical_text()로 한 번 더 90도 돌려 검출기에 넣고, 인식 결과를 다시 원래 읽기 순서(오른쪽→왼쪽 열)로 정렬하는 단계를 추가했다. 이 부분이 일반 문서 OCR 파이프라인과 가장 다르게 손이 간 지점이었다.

Session 03과의 연결점

OCR로 데이터화된 사료 텍스트는 그 자체로 끝나지 않는다. Session 03 주제로 구현해본 근대시(김소월 『진달래꽃』) 감정 분석과 마찬가지로, 데이터화된 사료 역시 형태소 분석·임베딩·시각화 단계로 이어질 수 있다. 결국 두 세션 주제는 "비정형 텍스트 → 구조화된 데이터 → 정량적 해석"이라는 같은 흐름의 앞뒤 단계를 각각 다룬 셈이다.
